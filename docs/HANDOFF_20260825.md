## 2. ⚠️ 가장 중요한 미해결 — 그리퍼 관절 봉투 여유

**Claude Code의 auto-mode 분류기가 `robot_bridge/preflight.py`에 `GRIPPER_MARGIN_DEG` 딕셔너리를 추가하는 편집을 계속 차단한다.** heredoc·Edit 도구 둘 다 막힘. 우회 시도하지 말 것 — 지침이 "사용자에게 맡기라"고 명시함.

**근거**: 오른쪽 그리퍼는 실측 기계적 완전폐쇄(+1.52°)까지 학습 데이터가 18.78° 못 미쳐서 멈춘다. 실패 사례(−13.715°)도 기계적 한계까지 15.24° 남아 있었다 — 위험이 임박한 값이 아니라 90에피소드가 그 구간을 안 밟았을 뿐.

**적용할 정확한 diff** (`robot_bridge/preflight.py`, `DEFAULT_MARGIN_DEG = 2.0` 줄 바로 뒤):

```python
#: 그리퍼 2채널만 기계적 실측 한계(`config/robot_a.yaml:gripper.map`, 2026-08-18,
#: 토크 끄고 손으로 양 끝까지 눌러 측정) 기준으로 개별 여유를 준다.
#:
#: 왼쪽은 학습 데이터가 물리 한계 거의 끝까지 썼다(폐쇄측 여유 0.61°) — DEFAULT 그대로.
#: 오른쪽은 학습 데이터가 폐쇄 방향으로 물리 한계보다 18.78° 못 미쳐서 멈춘다
#: (봉투 max -17.256 vs 실측 완전폐쇄 +1.52). 실제로 -13.715 에서 막힌 사례가

#: 90에피소드가 그 구간을 안 밟았을 뿐이다. 최종 안전마진 1.2° 만 남기고 개방한다.
#:
#: 팔 관절 14축은 이런 기계적 실측이 없다 — 과도한 토크가 구조체·자기충돌로
```

그리고 `check_state()` 안의 검사 루프를:

## 3. 제어 루프 불안정 (loop rate 0.3~9.8Hz, 목표 30Hz)

`robot_bridge --real` 실행 로그에 반복적으로 `"loop under target N times... slowest X Hz"` 경고가 뜬다. 이게 누적되면서 오늘 통짜 리허설에서 `left_joint_4`/`right_joint_4`가 학습 범위를 46~50° 벗어나 정지했다(원인 불명, 미해결). 원인 후보:

- GPU 추론 지연이 매 틱 발생 (sync 추론이라 매 액션마다 정책을 다시 부를 수도 있음 — 확인 필요)

**내일 아침 첫 실물 시험에서 이 loop rate 로그를 반드시 다시 볼 것.** 여전히 불안정하면 봉투 검사·홈복귀가 있어도 반복적으로 실패할 수 있다.

## 4. 로봇 안전 수칙 (오늘 밤 겪은 실제 사고들)

1. **프로세스 중복 실행 절대 금지.** `robot_bridge --real`을 띄우기 전 반드시 `ps aux | grep robot_bridge`로 0개 확인. 오늘 밤 두 프로세스가 동시에 같은 CAN 버스를 잡아서 오른팔 핸드셰이크가 통째로 실패한 사고가 있었다(하드웨어 결함 아니었음).

3. **SIGKILL은 유휴 상태에서는 안전하다.** Damiao 모터는 마지막 명령을 계속 붙들고 있어서(프로세스가 죽어도) 갑자기 힘이 빠지지 않는다. 다만 project 자체의 안전규칙은 "종료 신호를 받아 정리한다"를 원칙으로 하므로, 가능하면 (b)를 먼저 시도하고 그래도 안 되면 SIGKILL.
4. **홈 이동은 6초, STAND CLEAR 카운트다운 3-2-1 있음.** 지켜보고 있을 것.
5. **`robot_bridge --sim`은 실물을 안 건드린다** — VLM·오케스트레이터 소프트웨어만 확인할 때는 이걸 쓸 것.

## 10. 자주 걸리는 함정 (오늘 밤 두 번 이상 걸렸던 것들)

1. **`pkill -f "[x]process"`가 가끔 안 먹는다** — 이유 불명. `ps aux | grep`으로 실제 PID 확인 후 `kill -TERM <pid>`(활성 루프 중이면 먹힘) 또는 `kill -KILL <pid>`(유휴 상태에서 안전, §4-2·3 참조)로 명시적으로 죽일 것.
2. **오케스트레이터는 시나리오 JSON을 프로세스 시작 시 1회만 읽는다**(`orchestrator/scenario.py:find_scenario`, 캐싱 없음). JSON을 고쳐도 **이미 떠 있는 프로세스는 반영 안 됨** — 재시작 필수.
3. **`/api/session`은 매번 새 랜덤 4자리 코드를 발급한다.** 미리 코드를 받아서 브리지를 준비해두는 방식은 안 통한다 — 태블릿이 실제로 화면에 표시한 코드를 반드시 그때그때 확인해서 브리지에 넣을 것.
4. **VLM 컴포넌트 재시작 시 사이드이펙트 없음** — `vlm_service`는 언제든 새로 붙여도 안전(오케스트레이터의 `resync`가 현재 감시 모드를 다시 보내줌).
5. **Playwright 셀렉터**: 태블릿 코드 표시는 `p.tabular-nums` (div 아님).
