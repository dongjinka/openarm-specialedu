# 뉴다이브 인턴십 오픈암 프로젝트 — 과제분석 구현 대응

2026.08.25 (월)

Ran 님의 과제분석(2026-08-21)을 시스템으로 옮기면서 **무엇이 그대로 구현됐고, 무엇이
바뀌었으며, 어떤 지표가 실제로 로그에서 나오는지**를 같은 순서로 정리한 문서입니다.
원 문서와 나란히 놓고 읽을 수 있게 절 번호를 맞췄습니다.

---

## 1. 아동이 실제로 하는 일 — 구현된 흐름

| 단계 | 아동 | 로봇 | 시스템 상태 |
|---|---|---|---|
| ① | 태블릿에 뜬 문자와 장난감 목록 확인 | 친구의 문자와 목록 제시 | `INTRO` → `SHOW_LIST` |
| ② | **(변경) 닫힌 가방을 로봇 앞에 놓음** | **(변경) "가방을 내 앞에 놓아줄래?"** | `SHOW_LIST` |
| ③ | 호명된 장난감을 찾아 책상 위에 올림 | 목록의 한 항목을 호명 | `REQUEST` → `WAIT_CHILD` |
| ④ | 오답이면 다른 물건으로 바꿔 다시 가져옴 | 정답 → 칭찬 후 가방에 넣고 닫음 · 오답 → 알려만 줌 | `JUDGE` → `CORRECT`/`INCORRECT` → `ROBOT_TURN` |
| ⑤ | ③~④를 3개만큼 반복 | 완료·잔여 항목을 화면에 표시 | `ROBOT_VERIFY` → `NEXT` |
| ⑥ | **(변경) 인사를 듣고 마무리** | "이제 갈 준비 완료!" 인사 | `COMPLETE` → `END` |

시뮬레이션으로 ①~⑥ 전 구간이 완주하는 것을 확인했습니다
(`tools/scenario_check.py`, 오답 1회·정체 1회·재호명 1회 포함).

### 원 문서에서 바꾼 것 — ②와 ⑥의 가방 여닫기

**가방은 로봇이 엽니다.** 아동이 지퍼를 여는 동작을 뺐습니다.

로봇 정책(GR00T)이 **"가방 열기 → 물건 넣기 → 가방 닫기"를 한 덩어리로** 학습했기
때문입니다. 학습 데이터 60에피소드를 확인한 결과 **모든 에피소드가 닫힌 가방에서
시작**합니다. 아동이 먼저 열어 두면 로봇은 학습에서 본 적 없는 장면을 마주하고,
그때 무엇을 할지는 보장되지 않습니다.

원 문서 2절이 *"소근육 정교성은 목표로 두지 않았습니다"* 라고 밝혀 주신 덕에
지퍼를 빼도 타겟 기능이 손상되지 않는다고 판단했습니다. **다만 대가가 있습니다** —
4절의 하위과제 2(과제 준비)가 사라져 지표 두 개를 잃습니다. 아래 4절에 적었습니다.

### 태스크 조건 — 구현 상태

| 원 문서 조건 | 구현 |
|---|---|
| 사람이 개입하지 않고 로봇의 안내만으로 진행 | ✅ 물체 인식·판정·발화·로봇 호출이 자동. 운영자는 **폴백**으로만 개입 |
| 물건을 가방에 넣는 동작은 로봇이 담당 | ✅ |
| 목록에 없는 장난감이 함께 놓여 아동이 대조 | ⚠️ **물리적으로 놓아야 합니다.** 시스템은 목록 밖 물체를 `other` 로 인식해 로봇을 움직이지 않습니다 |
| 태블릿에 완료·잔여 항목 표시 | ✅ 하단 일정표에 상시 노출 |

## 2. 타겟 기능 — 시스템이 어디서 관측하는가

| 실행기능 | 시스템에서의 관측 지점 |
|---|---|
| 작업기억 | 아동이 "뭐라고?" 라고 물으면 음성 인식이 **재호명 요청**으로 분류해 기록. 로봇은 위계를 올리지 않고 같은 말을 다시 합니다 |
| 선택적 주의 / 방해자극 억제 | 배치면에 올라온 물체를 영상 인식이 4분류(3종 + 목록 밖)합니다. 목록 밖이면 **로봇이 움직이지 않습니다** |
| 과제 개시 / 완수 | 요청 후 무변화가 이어지면 촉진 타이머가 발화를 다시 냅니다. 완주 여부는 `END` 도달로 기록 |
| 계획, 수행 / 자기점검 | 현재는 로봇이 순차 호명 — 원 문서 유의사항대로 계획 요구가 제한적입니다. 5절 확장 조건 참고 |
| 오류 수정 | 오답 후 아동이 물건을 바꾸는 과정을 그대로 기록. 같은 항목의 오답→정답 쌍으로 자가 정정을 셉니다 |

**물체 인식 정확도** — 실제 촬영 장면 프레임으로 측정했습니다.

| 구간 | 결과 |
|---|---|
| 물건이 책상에 놓인 판정 시점 | **20/20** |
| 배치면이 비었을 때 | **10/10** (오인식 없음) |
| 로봇이 넣은 뒤 사후 확인 | **10/10** |

## 3. 확인 부탁드리는 부분

### ① 무발화 구간이 예상보다 훨씬 깁니다

로봇이 가방을 열고 물건을 넣고 닫는 한 사이클이 **평균 46.3초**로 측정됐습니다
(최대 60.5초). 이 구간은 원 설계상 **발화가 금지**돼 있습니다 — 아동의 시선이
로봇 팔로 가야 하기 때문입니다. 3개면 **2분 18초 이상**이 무발화입니다.

실행 속도에 따라 최대 두 배까지 늘 수 있어 **5분에 가까워질 가능성**도 있습니다.

완화책으로 화면에 진행 단계를 넣었습니다. 학습 데이터의 그리퍼 움직임에서 뽑은
4단계이고, 60에피소드에서 경계가 매우 일관적이었습니다(표준편차 0.02):

> 가방을 열고 있어요 → 장난감을 가지러 가요 → 가방에 넣고 있어요 → 가방을 닫고 있어요

**이 길이가 자폐 아동에게 감당 가능한지, 완화책이 적절한지 판단을 부탁드립니다.**
숫자나 카운트다운은 띄우지 않았습니다(인지접근성 지침).

### ② 오답 피드백을 원 문서보다 **약하게** 잡았습니다

원 문서 ④는 *"오답 → '그건 아닌 것 같아'라고만 알려줌"* 입니다. 그런데 5절의
난이도 표에서는 *"정답 제시 → 최소 오류 신호"* 가 **난이도를 올리는 방향**이므로,
최소 신호는 어려운 쪽 끝입니다.

현재는 **아동이 성공 경험으로 끝나도록** 촉진을 단계적으로 올립니다:

```
말로 다시 요청  →  힌트("빨간색 블록이야")  →  시범(로봇이 가리킴)
```

상한에 닿아도 실패로 끝나는 경로는 없습니다. 대신 **자가 정정률이 순수하지 않습니다** —
힌트를 받고 고친 것과 스스로 고친 것이 섞입니다. 로그에 촉진 단계가 남으므로 사후에
`촉진 없이 정정한 경우`만 골라낼 수 있게 해 두었습니다.

**어느 쪽이 맞는지 정해 주시면 설정 한 줄로 바뀝니다.**

### ③ 관측할 수 없는 지표가 셋 있습니다

4절 표의 ❌ 항목입니다. 코드로 해결되지 않고 **활동 설계를 바꿔야** 하는 것들입니다.

## 4. 하위과제별 산출 지표

시뮬레이션 세션 1회를 돌려 실제로 로그에서 뽑아본 결과입니다.
✅ = 값이 나옴 · ❌ = 관측 불가

| 하위과제 | 권장 행동지표 | 산출 | 로그에서 나오는 값 |
|---|---|---|---|
| 1. 맥락 파악 | 시작까지 시간 | ✅ | 세션 시작 → 첫 호명까지 ms |
| | 재확인 여부 | ✅ | 재호명 요청 횟수 |
| 2. 과제 준비 | 개시 잠복시간 | ❌ | **가방 놓기 동작을 관측하지 않음** (1절 변경) |
| | 촉진 횟수 | ✅ | 촉진 발화가 나간 횟수 + 사유(정체·모르겠음·재호명) |
| 3. 목표 부호화 | 재호명 요청 횟수 | ✅ | 음성 의도 분류 결과 |
| 4. 시각적 탐색 | 탐색시간 | ✅ | 호명 → 물건을 올린 순간까지 ms |
| | 비목표물 접촉 | ❌ | **책상에 올리기 전 손의 움직임은 관측 밖** |
| 5. 대조·선택 | 정확도 | ✅ | 정반응 / 전체 시행 |
| | 오선택률 | ✅ | 오반응 / 전체 시행 + 호명 대상과 다른 것을 고른 횟수 |
| 6. 피드백 처리 | 피드백 후 반응시간 | ✅ | 오답 → 다음 시행까지 ms |
| 7. 오류 수정 | 자가 정정률 | ✅ | 같은 항목 오답→정답 쌍 (촉진 단계 함께 기록) |
| | 수정시간 | ✅ | 오답 → 정답까지 ms |
| 8. 진행 점검 | 누락률 | ✅ | 실제로 담긴 수 / 목록 수 |
| | 확인행동 | ❌ | **아동이 화면을 보는지는 시선 추적이 필요** |
| 9. 반복·전환 | 전환시간 | ✅ | 호명 간 간격 ms |
| | 중도이탈 | ✅ | `END` 도달 여부 |

**17개 중 14개가 나옵니다.**

### 탐색시간에 대한 주의

처음에는 "호명 → 판정 완료" 로 쟀는데, 그 안에 **영상 인식 대기(중앙 3.6초)** 가
섞여 실제보다 약 4.6초 큰 값이 나왔습니다. 지금은 **"호명 → 물건을 올린 순간"** 과
**"판정에 걸린 시간"** 을 따로 기록합니다. 연구 지표로는 앞의 값을 쓰시면 됩니다.

### [지표 해석 시 유의사항]

- **자가 정정률은 촉진과 섞입니다** (3절 ②). 촉진 단계가 함께 기록되므로 사후에
  분리할 수 있습니다.
- **탐색시간은 아동이 "물건을 놓고 물러난" 시점 기준**입니다. 손이 물체 위에 있는
  동안은 아직 놓지 않은 것으로 봅니다.
- **음성 지표는 인식이 실패하면 0으로 기록됩니다** — 말하지 않은 것과 구분되지
  않습니다. 발음이 불명확한 아동에게는 과소 추정될 수 있습니다.
- 모든 기록에 **밀리초 단위 시각**과 **순번**이 함께 남습니다. 같은 초에 일어난
  사건도 순서가 보존됩니다.

## 5. 기능별 과제 조건 및 난이도 조절 — 어디를 바꾸면 되는가

원 문서 5절의 조작 조건을 **설정 파일 한 곳**(`scenarios/*.json`)에 모았습니다.
코드 수정 없이 바뀝니다.

| 타겟 기능 | 조작 가능한 조건 | 설정 항목 | 지금 값 |
|---|---|---|---|
| 작업기억 | 항목 수 | `checklist` | 3개 (꽃·고래·나무) |
| | 목록 노출 시간 | *(미구현 — 상시 표시 고정)* | 상시 |
| 선택적 주의 | 방해자극 수·유사도 | **물리적 배치** | 책상에 직접 놓습니다 |
| | 호명 대상만 정답 처리 | `strict_order` | `true` |
| 목표 유지·지속 | 항목 수 | `checklist` | 3개 |
| | 촉진까지 기다리는 시간 | `stall_timeout_ms` | 20초 |
| 오류 모니터링·수정 | 피드백 구체성 | `prompt_hierarchy` | `["verbal","hint","model"]` |
| | ↳ **최소 오류 신호로** | 같은 항목 | `["verbal"]` 로 바꾸면 됩니다 |
| | 재시도 기회 | `max_retries_per_item` | 3 |
| 자기점검 | 완료/잔여 표시 | *(미구현 — 상시 표시 고정)* | 상시 |
| 계획(확장) | 전체 목록 일괄 제시 | *(미구현)* | 개별 호명 |

**미구현 셋**은 원 문서가 "확장 조건"으로 표시한 것들이라 이번 범위에서 제외했습니다.
필요하시면 알려주세요 — 목록 노출 시간과 완료 표시 최소화는 화면 작업이라 비교적 가볍고,
전체 목록 일괄 제시는 진행 방식이 바뀌므로 별도 논의가 필요합니다.

## 6. 시스템 Flow

```
   아동                     태블릿                오케스트레이터            로봇
    │                        │                        │                    │
    │  ① 문자·목록 확인  ◀────│◀── 발화·표정 ──────────│                    │
    │                        │─── 발화 끝났음 ───────▶│                    │
    │                        │                        │                    │
    │  ③ 물건을 책상에 올림                            │                    │
    │       │                                         │                    │
    │       └──▶ 카메라 ──▶ 영상 인식 ──── 판정 ──────▶│                    │
    │                        │◀── 정답/오답 발화 ─────│                    │
    │                        │                        │                    │
    │  "뭐라고?"  ──▶ 음성 인식 ──── 의도 ───────────▶│  (같은 말 다시)     │
    │                        │                        │                    │
    │  ④ 정답이면            │                        │─── 넣어줘 ────────▶│
    │     로봇이 담는 것을 봄  │◀── 진행 단계 ──────────│◀── 진행 신호 ──────│
    │                        │                        │◀── 완료 ───────────│
    │                        │                        │                    │
    │                        │         사후 확인 ◀── 영상 인식             │
    │                        │         (물건이 들어갔나 · 가방이 닫혔나)     │
    │                        │                        │                    │
    │  ⑤ 다음 항목 반복       │◀── 잔여 항목 ──────────│                    │
    │  ⑥ 인사               │◀── 완료 ───────────────│                    │
```

**모든 판단은 오케스트레이터 한 곳을 지납니다.** 영상 인식이 로봇을 직접 부르는 경로는
존재하지 않고, 이는 문서 규칙이 아니라 코드 구조로 막혀 있습니다. 아동 앞에서
검증되지 않은 동작이 나오지 않도록 하기 위한 것입니다.

**안전 장치** — 카메라 3대 중 하나라도 끊기면 새 턴이 시작되지 않습니다. 로봇의
관절이 학습 범위를 벗어나면 추론하지 않고 멈춥니다. 운영자는 언제든 일시정지·중단할 수
있고, 로봇이 실패하면 **"로봇의 실수"로 안내**해 아동이 자기 실패로 받지 않게 합니다.
