# VLM 판별 평가 — 60에피소드 씬

`labels_45.csv` 는 **120epi 씬** 라벨이라 지금 씬에 쓸 수 없다. 배치 구역의 위치도
물체 배열도 다르다. 이 세트가 현행 기준이다.

## 재현

```bash
.venv/bin/python tools/extract_eval_set.py --out /tmp/eval60
.venv/bin/python tools/eval_vlm.py --labels eval/labels_60epi.csv --root /tmp/eval60
```

프레임은 데이터셋 영상에서 뽑으므로 리포에 두지 않는다. `/tmp` 가 지워지면 첫 명령을
다시 돌린다. 라벨(`labels_60epi.csv`)만 영구 보존한다.

## 구간을 나눠 본다

섞으면 숫자가 뜻을 잃는다.

| 구간 | 무엇 | 왜 나누나 |
|---|---|---|
| **판정 시점** | 물건이 책상에 놓여 있거나 배치면이 비었다 | 실제로 판정이 일어나는 순간 |
| **사후 확인** | 로봇이 담은 뒤 | `ROBOT_VERIFY` 경로 |
| 경계 프레임 | 사람 손이 물체를 놓는 중 | **감시의 안정성 게이트가 걸러낼 구간** — 참고용 |

경계 프레임은 손이 빠지기 전이라 사람이 봐도 애매하다. 실제 운영에서는 N프레임 연속
정지를 확인한 뒤에야 판정하므로 이 순간이 오지 않는다.

## 결과 — google/gemini-3.7-flash, 2026-08-25

```
판정 시점   20/20  100.0%
사후 확인   10/10  100.0%
경계 프레임   2/ 5   40.0%   (참고용)
```

- **방해자극 누출 0건** — 체크리스트에 없는 것을 tree/flower/whale 로 부른 적이 없다
- 물체를 다른 물체로 잘못 부른 경우 **0건**. 오답 3건은 전부 경계 프레임에서
  `none` 을 물체로 본 것이고, 로봇이 움직이는 방향의 오류이므로 게이트가 필요하다
- 지연 중앙 4.10초 · p95 7.31초 (동시 3). `judge_timeout_ms` 15초 안에 들어온다

## 모델을 바꾸면 다시 잰다

`prompts.py` 는 이 모델의 응답을 보며 다듬은 것이다 — 물체 3종의 색·형태 서술,
가림 처리 규칙, `confidence` 사용법 전부. 다른 모델로 바꾸면 위 숫자는 근거를 잃는다.

`.env` 의 `VLM_PROVIDER` · `OPENAI_MODEL` 을 바꾼 뒤 같은 명령을 돌리고,
결과를 `eval/results_60epi_<model>.json` 으로 남긴다.
